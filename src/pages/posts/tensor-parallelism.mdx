[DP](/posts/data-parallelism/)에서는 모델을 복제하고 서로 다른 입력을 맡겼습니다. **텐서 병렬화(Tensor Parallelism, TP)에서는** 같은 입력의 한 연산을 여러 GPU가 함께 계산합니다. 텐서는 여기서 벡터나 행렬처럼 여러 값을 배열한 데이터를 뜻합니다.

같은 행렬 곱도 어느 방향으로 나누느냐에 따라 GPU가 만드는 결과의 의미가 달라집니다. 먼저 완성된 출력 조각과 부분합을 구별하고, 두 선형 연산을 연결해 불필요한 통신을 줄이는 방법을 보겠습니다. 마지막에는 어텐션과 전체 실행에 적용할 때 확인할 조건을 짚겠습니다.

## 출력 방향으로 나누기

행렬 곱 `Y = XW`에서 X를 `[1, 2]`, W의 두 행을 `[1, 3]`, `[2, 4]`로 두겠습니다. 결과는 `[5, 11]`입니다. 첫 출력은 W의 첫 열과, 둘째 출력은 둘째 열과 X를 곱해 더한 값입니다.

[![W의 열을 나누면 GPU 0이 5, GPU 1이 11을 완성합니다.](/images/tensor-parallelism/01-columns.png)](/images/tensor-parallelism/01-columns.png)

W의 열을 나누면 GPU 0은 첫 열만 보관하고 5를 계산하며, GPU 1은 둘째 열만 보관하고 11을 계산합니다. 두 GPU 모두 X 전체가 필요하지만 W는 절반씩 갖습니다. **각 결과는 다른 출력 위치의 완성된 값**입니다. 5와 11을 더하는 것이 아니라 나란히 놓아야 전체 Y가 됩니다.

다음 연산이 Y 전체를 각 GPU에서 요구하면 All-Gather로 조각을 모을 수 있습니다. 반대로 다음 연산도 자기 조각만으로 진행할 수 있다면 즉시 모을 필요가 없습니다. 분할 방식의 이름만으로 통신을 결정하지 않고 다음 연산의 입력 요구를 봐야 합니다.

## 누적하는 방향으로 나누기

이번에는 W의 행과 X의 대응하는 원소를 나눠 갖겠습니다. GPU 0은 X의 1과 W의 첫 행을 곱해 `[1, 3]`을 얻고, GPU 1은 X의 2와 둘째 행을 곱해 `[4, 8]`을 얻습니다.

[![GPU 0의 [1,3]과 GPU 1의 [4,8]을 위치별로 더해 [5,11]을 얻습니다.](/images/tensor-parallelism/02-rows.png)](/images/tensor-parallelism/02-rows.png)

이번 결과들은 전체 출력과 원소 수가 같지만 각각 일부 곱셈만 반영한 **부분합**입니다. 같은 위치끼리 더해야 `[5, 11]`이 됩니다. 두 결과를 이어 붙이면 원래 행렬 곱과 다른 계산이 됩니다.

모든 GPU가 Y 전체를 써야 한다면 All-Reduce가 자연스럽습니다. 한 GPU만 필요하면 Reduce, 합산된 결과를 나눠 갖고 싶으면 Reduce-Scatter를 생각할 수 있습니다. 결국 통신은 ‘조각인가 부분합인가’와 ‘완성된 값을 누가 필요로 하는가’에서 도출됩니다.

## 두 선형 연산을 이어서 배치하기

모델의 MLP에는 특징을 늘리는 선형 연산, 활성화, 다시 특징을 줄이는 선형 연산이 이어집니다. 여기서는 원소별 활성화 f를 둔 단순한 `Y = f(XU)V`로 보겠습니다. 원소별 활성화는 각 값을 다른 위치의 값 없이 변환하는 계산입니다.

[![첫 선형 연산의 열 분할과 둘째 선형 연산의 행 분할을 연결해 중간 All-Gather를 피하는 MLP 흐름입니다.](/images/tensor-parallelism/03-mlp.png)](/images/tensor-parallelism/03-mlp.png)

첫 가중치 U를 출력 열로 나누면 중간값 H도 나뉩니다. 각 GPU는 자기 H 조각에 f를 적용할 수 있습니다. 이어서 둘째 가중치 V를 같은 중간 특징에 대응하는 행으로 나누면, 자기 H 조각으로 최종 출력의 부분합을 계산합니다. 마지막에 부분합을 합치면 됩니다.

따라서 **두 선형 연산 사이에서 H 전체를 모으는 통신을 생략할 수 있습니다.** [Megatron-LM 논문](https://arxiv.org/abs/1909.08053)은 이런 열·행 분할의 연결을 사용합니다. 게이트가 있는 MLP라면 원소별로 곱할 두 분기의 조각도 서로 맞아야 합니다. 또한 비선형 함수는 일반적으로 `f(P₀ + P₁)`과 `f(P₀) + f(P₁)`이 다르므로, 아직 합산하지 않은 부분합에 임의로 활성화를 적용하면 안 됩니다.

## 어텐션과 전체 실행에 적용하기

어텐션에서는 여러 head가 각각 Q·K·V로 결과를 계산한다는 구조를 활용할 수 있습니다. head를 나누고 각 head의 입력 투영을 대응시킨 뒤, 출력 투영에서 생기는 부분합을 합치는 식입니다. 다만 head 수가 나눠지는지, K·V를 공유하는 모델에서는 어떤 데이터가 복제되는지 등 실제 모델의 구조를 확인해야 합니다.

TP는 가중치와 연산 일부를 나누어 GPU당 부담을 줄일 수 있지만 모든 메모리가 TP 크기만큼 줄지는 않습니다. 복제된 입력, 임시 버퍼와 실행 중 상태도 있습니다. 작은 행렬을 너무 잘게 나누면 각 GPU의 계산 효율이 떨어질 수도 있습니다.

특히 여러 층에서 반복되는 통신은 연결의 지연과 대역폭에 영향을 받습니다. 계산이 줄어든 시간보다 통신과 대기가 더 늘었다면 한 입력의 완료 시간도 나빠질 수 있습니다. TP를 적용한 뒤에는 GPU별 연산량뿐 아니라 **필요한 결과를 기다리는 구간과 전체 완료 시간**을 확인해야 합니다.
