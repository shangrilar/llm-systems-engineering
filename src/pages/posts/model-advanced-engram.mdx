[N-gram 임베딩](/posts/model-advanced-ngram-embedding/)에서는 짧은 토큰 묶음으로 표의 주소를 정하고 학습된 벡터를 읽었습니다. 하지만 같은 묶음이 더 긴 문맥에서도 항상 같은 역할을 하는 것은 아닙니다. 조회한 표현을 이번 문맥에서 얼마나 사용할지도 정해야 합니다.

[Engram](https://arxiv.org/html/2601.07372v1)은 **주소는 토큰 묶음으로 정하고, 반영량은 현재 문맥 표현으로 조절하는 모듈**입니다. 먼저 모델 안의 삽입 위치를 본 뒤 조회와 gate 계산을 확대하겠습니다. 이어 시간 방향의 보정과 residual 결합을 살펴보고, 왜 입력 대신 중간 층에 넣는지 돌아보겠습니다.

## 모델 안의 Engram

그림 1은 Engram이 들어가는 위치를 보여줍니다. [원 논문의 30층 실험](https://arxiv.org/html/2601.07372v1#A1.T5)에서는 1부터 센 2층과 15층에 삽입했습니다.

<a href="/images/model-advanced-engram/00-layer-map.png?v=811d70bf07c1" id="figure-1"><picture><source width="720" height="3110" media="(max-width: 600px)" srcSet="/images/model-advanced-engram/00-layer-map-mobile.png?v=b970bbb0061c" /><img width="2400" height="2626" src="/images/model-advanced-engram/00-layer-map.png?v=811d70bf07c1" alt="입력 임베딩은 유지되고 30층 중 2층과 15층의 Attention 앞에서 Engram 출력을 현재 hidden에 더한다." loading="lazy" /></picture></a>

기본 토큰 임베딩을 거친 현재 표현 h에 Engram 출력 y를 더한 뒤, 해당 층의 Attention과 MoE가 계산됩니다. 각 삽입 위치는 그 깊이에서 얻은 h로 별도의 gate를 계산합니다. 그림은 먼저 하나의 residual stream을 보여주며, 여러 branch로 확장한 경우는 그림 4에서 살펴봅니다.

Engram 안에는 토큰 ID로 주소를 미리 정하는 조회 경로와, 앞선 모델 계산에서 얻은 h를 사용하는 문맥 경로가 있습니다.

## 토큰 묶음으로 기억 조회

그림 2의 A는 원래 token ID가 두 경로로 갈라지는 모습입니다. 파란 경로는 기존 임베딩과 backbone을 거쳐 현재 문맥 <math><msub><mi>h</mi><mtext>t</mtext></msub></math>를 만듭니다. 청록색 경로는 조회용 ID로 변환한 뒤 표의 행을 읽어 <math><msub><mi>e</mi><mtext>t</mtext></msub></math>를 만듭니다. 여기의 e는 앞 글의 기본 토큰 임베딩 e(B)와 달리 **Engram에서 조회한 벡터**입니다.

<a href="/images/model-advanced-engram/01-lookup-and-context.png?v=4bc93c5d8cc1" id="figure-2"><picture><source width="720" height="4832" media="(max-width: 600px)" srcSet="/images/model-advanced-engram/01-lookup-and-context-mobile.png?v=8f3e4b9eab33" /><img width="2400" height="5584" src="/images/model-advanced-engram/01-lookup-and-context.png?v=4bc93c5d8cc1" alt="원래 token ID에서 기본 embedding 경로와 canonical ID 조회 경로가 갈라진다. 조회 벡터를 Key와 Value로 변환하고 문맥 hidden으로 gate를 만든다." loading="lazy" /></picture></a>

조회에 사용하는 canonical ID는 대소문자나 표기 정규화로 같은 텍스트가 되는 토큰들을 미리 묶은 ID입니다. [논문 §2.2](https://arxiv.org/html/2601.07372v1#S2.SS2)의 변환은 조회 경로에만 적용되며, 언어 모델의 원래 token ID와 임베딩은 유지됩니다.

B 패널에서 끝 세 토큰이 A, B, C라면 2-gram은 (B,C), 3-gram은 (A,B,C)입니다. 길이마다 해시 head 두 개를 둔 축소 예시이므로, 각기 다른 네 표에서 읽은 벡터를 이어 붙입니다.

이어 붙인 <math><msub><mi>e</mi><mtext>t</mtext></msub></math>의 폭은 <math><msub><mi>d</mi><mtext>mem</mtext></msub></math>이고, backbone의 <math><msub><mi>h</mi><mtext>t</mtext></msub></math>는 d차원입니다. C 패널의 <math><msub><mi>W</mi><mtext>K</mtext></msub></math>와 <math><msub><mi>W</mi><mtext>V</mtext></msub></math>가 조회 벡터를 각각 d차원의 Key와 Value로 바꿉니다. 열벡터 표기에서 두 투영의 크기는 [d × <math><msub><mi>d</mi><mtext>mem</mtext></msub></math>]입니다.

Key는 현재 문맥과 비교하고, Value는 그 결과에 따라 반영됩니다.

## 문맥에 따른 반영량

[논문 §2.3의 gate](https://arxiv.org/html/2601.07372v1#S2.SS3)는 h와 k를 각각 RMSNorm으로 정규화하고 내적을 구합니다. 이를 √d로 나눈 뒤 sigmoid를 적용해 0과 1 사이의 scalar α를 얻습니다. α를 v의 모든 성분에 곱한 결과가 gated value입니다.

그림 3은 앞 문맥 P와 Q가 달라도 끝 세 토큰 A, B, C가 같은 경우입니다. 최대 길이 N=3이므로 두 경우의 (B,C), (A,B,C) 조회와 k, v는 같습니다. 긴 문맥의 영향을 받은 h만 바꾼 교육용 예시입니다.

<a href="/images/model-advanced-engram/02-context-gate-numbers.png?v=91cc4a1c6b49" id="figure-3"><picture><source width="720" height="4090" media="(max-width: 600px)" srcSet="/images/model-advanced-engram/02-context-gate-numbers-mobile.png?v=88749f7694a3" /><img width="2400" height="3376" src="/images/model-advanced-engram/02-context-gate-numbers.png?v=91cc4a1c6b49" alt="두 입력의 끝 ABC와 조회 Key·Value는 같지만 hidden 방향이 달라 gate가 약 0.8044와 0.1956이 된다." loading="lazy" /></picture></a>

d=2, k=[1,1], v=[2,−1]이고, h만 A의 [1,1]에서 B의 [−1,−1]로 바꿉니다. RMSNorm의 gain을 1로 두고 ε를 생략하면 두 경우의 h와 k는 정규화 후에도 값이 같습니다.

A에서는 h와 k의 내적이 1×1 + 1×1 = 2입니다. B에서는 −1×1 + −1×1 = −2입니다. √2로 나눈 점수는 각각 √2와 −√2입니다. Sigmoid의 식 1 / (1 + exp(−s))에 이 점수 s를 넣으면 약 0.8044와 0.1956이 됩니다.

| h | Gate α | 결과 αv |
|---|---|---|
| [1,1] | 약 0.8044 | [1.6089, −0.8044] |
| [−1,−1] | 약 0.1956 | [0.3911, −0.1956] |

결과는 반올림 전 α로 계산했습니다. 두 결과의 방향과 성분 비율은 같고 전체 반영량이 달라집니다. **Scalar 하나가 Value 전체를 조절**하므로 성분마다 다른 계수를 곱하지 않습니다.

α는 사실이 맞을 확률이 아니라, 예측 loss를 통해 학습한 반영 계수입니다.

## Residual stream에 결합

그림 4는 위치별 gated value를 모은 Ṽ[T×d]가 어떻게 backbone으로 돌아가는지 보여줍니다.

<a href="/images/model-advanced-engram/03-convolution-and-residual.png?v=2df40a6ccd77" id="figure-4"><picture><source width="720" height="5710" media="(max-width: 600px)" srcSet="/images/model-advanced-engram/03-convolution-and-residual-mobile.png?v=31d265270f4b" /><img width="2400" height="5564" src="/images/model-advanced-engram/03-convolution-and-residual.png?v=2df40a6ccd77" alt="Gated value에 정규화, 간격 3의 depthwise causal convolution, SiLU를 적용하고 원래 값을 더한 뒤 backbone hidden에 다시 더한다." loading="lazy" /></picture></a>

첫 번째 경로는 Ṽ에 RMSNorm, depthwise causal convolution, SiLU를 차례로 적용합니다. 그리고 **변환 전 Ṽ를 다시 더해** Engram 출력 Y를 만듭니다. 두 번째 덧셈은 이 Y를 **원래 backbone의 H에 더하는 것**입니다. 첫 우회 경로는 조회 정보 자체를 남기고, 두 번째 우회 경로는 기존 문맥 표현을 남깁니다. H+Y가 이후 Attention과 MoE의 입력이 됩니다.

B 패널은 convolution이 읽는 위치를 확대합니다. [논문 §2.3](https://arxiv.org/html/2601.07372v1#S2.SS3)의 kernel 크기는 w=4, dilation은 δ=N입니다. N=3이면 현재 t와 t−3, t−6, t−9를 읽습니다. 시작부에서 과거가 부족하면 padding을 사용합니다.

Depthwise convolution은 정규화된 벡터의 같은 성분 c에서 이 네 시점의 값을 가중합합니다. Convolution 단계 자체는 서로 다른 성분을 섞지 않습니다.

C 패널은 [mHC](/posts/model-advanced-hc-mhc/)의 여러 residual branch를 보여줍니다. 같은 삽입 위치에서 조회 표와 Value 투영을 공유하고, Key 투영과 gate는 branch마다 따로 둡니다. 따라서 같은 Value라도 branch별 hidden에 따라 반영량이 달라집니다. 그림은 실제 실험의 네 branch 중 두 개를 펼쳤습니다.

## 중간 층에 배치하는 이유

그림 5는 입력에서 N-gram 표현을 결합하는 경우와 Engram처럼 중간 층에서 결합하는 경우를 비교합니다. 조회를 시작하는 시점과 표현을 합치는 시점이 다릅니다.

<a href="/images/model-advanced-engram/04-input-versus-middle.png?v=f0ae9e33f166" id="figure-5"><picture><source width="720" height="2274" media="(max-width: 600px)" srcSet="/images/model-advanced-engram/04-input-versus-middle-mobile.png?v=8b2c74269c16" /><img width="2400" height="1914" src="/images/model-advanced-engram/04-input-versus-middle.png?v=f0ae9e33f166" alt="입력 결합과 중간 결합을 비교한다. 중간 hidden으로 문맥 gate를 계산하며 주소가 미리 정해지는 조회·전송은 앞선 GPU 계산과 겹칠 수 있다." loading="lazy" /></picture></a>

입력에 더한 표현은 이후 층들이 활용법을 학습합니다. 중간에서 결합하면 앞선 Attention으로 문맥을 얻은 h를 gate에 사용할 수 있습니다. 다만 삽입이 늦어질수록 앞선 층은 조회 정보를 활용하지 못합니다.

[원논문 그림 2(b)](https://arxiv.org/html/2601.07372v1#S2.F2)처럼 추론에서는 조회 주소가 토큰 ID로 미리 정해집니다. 따라서 GPU가 앞선 블록을 계산하는 동안 호스트 메모리의 표 조회와 GPU 전송을 시작할 수 있습니다. 합류 시점에는 e와 h가 모두 필요하며, 중첩되는 정도는 전송 시간과 앞선 블록의 계산 시간에 달려 있습니다. 그림의 막대는 측정값이 아닌 실행 순서 예시입니다.

[논문 §6.2](https://arxiv.org/html/2601.07372v1#S6.SS2)의 12층 모델 단일 삽입 실험에서는 2층이 가장 좋았습니다. 이는 그림 1의 30층 모델에서 사용한 2·15층 배치와 다른 실험이며, 최적 위치는 모델 효과와 조회 지연을 함께 고려해야 합니다.

토큰 묶음이 조회 주소를, 삽입 층의 문맥 표현이 반영량을 정합니다. 이 분리 덕분에 조회를 먼저 시작하고, 계산과 전송이 만나는 층을 선택할 수 있습니다.
